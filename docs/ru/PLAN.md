## 1. Команда и роли

Ядро команды = 3 человека. Каждый владеет кодом в репозитории (критерий предзащиты: *видимая активность всех*). Детальные пошаговые карточки задач: **[ROLE_M1](ROLE_M1.md) · [ROLE_M2](ROLE_M2.md) · [ROLE_M3](ROLE_M3.md)**.

| Кто | Миссия | Докладывает |
|---|---|---|
| **M1 — тимлид: инфраструктура, методы, интеграция** | Репозиторий, inference-харнесс, библиотека промптов (plain + S1 + S4), Colab smoke-test, финальная сборка + тег; ведёт ежедневный синк и журнал решений | постановку, план, методы |
| **M2 — лид по данным** | Пассажи из Spoken-SQuAD, генерация B/C-вопросов по транскриптам, верификация не-автором, заморозка `pilot.jsonl`, data card | датасет |
| **M3 — лид по оценке** | Классификатор ответов (ответ/отказ/уклонение), LLM-судья + аудит, модуль метрик, пилотный прогон E1+S1, таблица и график результатов | результаты |

**M4 (опциональный 4-й участник) — гибкий бэклог, только если присоединится:** оставшиеся стратегии S2/S3/S5, smoke-test S4, консолидация обзора литературы; основная фаза: обёртка Qwen2.5-Omni, подготовка абляции с деградацией.
**Правило онбординга:** присоединился до **10 июля** → берёт гибкий бэклог целиком и докладывает слайд о методах. 11 июля → smoke-test S4 + помощь с верификацией + подготовка к Q&A. Не присоединился → задачи уходят во 2-ю неделю основной фазы; план не меняется.

## 2. Контракты данных (КАНОНИЧЕСКИЕ — в ролевых файлах лежат копии для удобства)

Изменения полей — только через `docs/decisions.md` в тот же день, никогда молча.

**Манифест** (производит M2 → читают все) — `data/manifests/pilot.jsonl`, по JSON на строку:
```json
{"id": "sq-0421-C2",               // уникальный: источник–пассаж–категория+номер
 "audio_path": "data/audio/….wav",
 "transcript": "…",                // точный текст аудио
 "question": "…",
 "category": "C",                  // A сказано | B выводимо | C неотвечаемо
 "subtype": "absent-attribute",    // A: "stated" · B: "inference" · C: C1 absent-entity, C2 absent-attribute, C3 false-premise, C4 off-topic
 "gold_answer": "UNANSWERABLE",    // эталонный ответ; для C — литерал UNANSWERABLE
 "source": "spoken-squad",         // spoken-squad | tts
 "generator": "gpt-4o-mini/b-v2",  // модель/версия промпта; "native" — исходный вопрос SQuAD
 "verified_by": "M3"}              // проверяющий — никогда не автор
```

**Ответы** (производит харнесс M1 → читает M3) — `results/<run_id>/responses.jsonl`:
```json
{"id": "sq-0421-C2", "model": "qwen2audio", "strategy": "plain",
 "response": "…", "samples": null,   // samples = список из 5 ответов для s4_consistency
 "latency_s": 3.1, "ts": "2026-07-11T14:02:11", "prompt_version": "plain.txt"}
```

**Оценённые ответы** (производит M3) — строка ответа плюс:
```json
{"label": "answer|abstain|hedge", "correct": true, "judge": "rules|human|llm-v1"}
```

## 4. Уровни объёма — каждый содержит предыдущий; контрольная точка — **вечер 10 июля**

Что каждый уровень *утверждает* научно — в [PROPOSAL_RU.md §7](PROPOSAL.md).

| Измерение | **Уровень 1 МИНИМУМ** (аварийный) | **Уровень 2 СРЕДНИЙ** (дефолт) — добавляет | **Уровень 3 МАКСИМУМ** (stretch) — добавляет |
|---|---|---|---|
| Датасет | 60 элементов (20/20/20), C = только C1+C2, только аудио Spoken-SQuAD | пилот 90–120 с C1–C4, TTS-подстраховка; основная фаза 600–900, ~50/50 TTS/естественное | 1000–1200; + срез LibriSpeech, паралингвистические B-вопросы, набор с деградацией (шум/обрезка) |
| Системы | Qwen2-Audio (int8, Colab); каскад — если успеем | каскад обязателен; основная фаза + Qwen2.5-Omni → 3 | + SALMONN + одна закрытая референс-модель → 5 |
| Стратегии | plain + S1 | + S4 реализован; основная фаза S1–S5 | + S6 детектор по внутренним сигналам (logprob / semantic entropy) |
| Оценка | правила + вручную (один вечер втроём) | LLM-судья v1 + ручной аудит 30 элементов | + углублённая калибровка |
| Метрики | 3 базовые доли + интервалы Уилсона | + F1, risk–coverage/AURC, RGI | + AUROC детекторов, кривые деградации |
| Дополнительно | — | анализ E3 (эпистемический градиент, таксономия подтипов) | LoRA-эксперимент; transfer-оценка на AQUA-Bench/HalluAudio; релиз датасета на HF + черновик статьи |

**Правила переключения:**
- **Вниз на Уровень 1**, если на контрольной точке вечером 10 июля: пилот не заморожен ИЛИ харнесс не работает ИЛИ основной участник выбыл на ≥2 дня. Это срез объёма, а не перепланирование — Уровень 1 к этому моменту уже построен (в этом смысл надстройки). Прямого пути Уровень 1 → Уровень 3 нет.
- **Вверх на Уровень 3** только при ВСЕХ условиях: M4 присоединился до 10 июля; вехи 9 июля выполнены в срок; после предзащиты — выданы GPU + небольшой API-бюджет.
- **Лестница дополнений Уровня 3** (принимаем сверху вниз, отбрасываем снизу вверх; ступень никогда не угрожает критериям готовности Уровня 2): 1) полная сетка S1–S5 на 3 системах → 2) SALMONN + закрытая референс-модель → 3) LibriSpeech + паралингвистические B → 4) набор с деградацией + кривая → 5) детектор S6 → 6) transfer-оценка → 7) LoRA-эксперимент → 8) релиз на HF + черновик статьи. Если любая неделя основной фазы сдвигается на ≥3 дня — отбрасываем нижнюю непринятую ступень, больше ничего не меняем.

## 5. Координация

- **Ежедневный 15-минутный синк** в фиксированное вечернее время; Telegram-группа для асинхрона.
- **`docs/decisions.md`** — каждое решение: дата, что, почему. Изменения схем — всегда сюда.
- **Git-процесс:** ветки `m1/…`, `m2/…`, `m3/…`; в `main` — PR + 1 ревью; прямых пушей нет.
- **Верификация:** каждый сгенерированный элемент датасета проверяет не-автор (протокол в [ROLE_M2](ROLE_M2.md), Задача 3).

## 7. Чек-лист предзащиты и спикеры

| Критерий | Наши доказательства |
|---|---|
| ✅ Команда понимает цель | Слайды с проблемой, RQ и дизайном A/B/C своими словами |
| ✅ Реалистичный ясный план | Этот документ: вехи, система уровней с контрольной точкой 10 июля, ролевые файлы |
| ✅ Осмысленные выполнимые эксперименты | E1/E2/E3 с определёнными метриками; пилот уже прогнан на Colab |
| ✅ Начальный прогресс | Репозиторий: харнесс, пайплайн данных, метрики, пилотные цифры (plain vs S1) |
| ✅ Команда активна и готова | 3 именованные роли с личными результатами + отделяемый объём для опционального 4-го; коммиты от всех |

**Презентация (10 слайдов):** проблема+пример → RQ → пробел в литературе → дизайн датасета → модели → эксперименты → метрики → пилотные цифры → таймлайн+уровни → команда.
**Спикеры:** M1 — постановка/план + методы (методы забирает M4, если присоединился до 10 июля), M2 — данные, M3 — результаты.
**Подготовка к Q&A:** «чем отличаетесь от AQUA-Bench?» · «что если GPU задержат?» · «как оцениваете свободные ответы?» · «что изменится втроём?»

## 8. Превью основной фазы (после одобрения, с GPU Яндекс Облака)

Недели 2–3: масштабирование датасета; полная сетка E1+E2 — **регулятор объёма:** втроём → 3 системы × 5 стратегий; с M4 → 4 × 6. Недели 4–5: анализ E3, таксономия ошибок, аудиты (+ ступени лестницы Уровня 3, если вошли). Неделя 6: отчёт + финальная презентация; возможная цель: workshop-трек ICASSP/Interspeech.
