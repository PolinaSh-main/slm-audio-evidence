# Роль M2 — Лид по данным: построить тестовый набор

## Краткая суть проекта

- **Speech LLM** — ИИ-модель: звукозапись + письменный вопрос на входе, текстовый ответ на выходе.
- Проблема: когда в записи нет ответа, модели его выдумывают (**галлюцинация**). Аудио: «я люблю яблоки». Вопрос: «какого цвета была куртка?» Модель: «синяя».
- Мы проверяем это записями с тремя видами вопросов: **A** — ответ произнесён в записи; **B** — не произнесён, но выводится из сказанного; **C** — ответа в записи нет вообще (модель должна отказаться отвечать).
- **Всё, что команда измеряет, работает на данных, которые строишь ты.** Если вопрос «C» втайне отвечаем — все цифры ниже по цепочке неверны. Твоя аккуратность = качество проекта.
- Результат: репозиторий + слайды до **12 июля, 23:00 UTC+3**; твой замороженный датасет — до **10 июля**.

## Твоя миссия

Построить тестовый набор, каждой метке которого можно верить. Взять готовое аудио, сгенерировать B- и C-вопросы чат-ИИ **по транскриптам** (никогда по аудио), отфильтровать механически, затем дать каждый элемент на проверку тиммейту, который его не создавал. Сдать замороженный манифест и data card.

## Формат записи (от него зависит вся команда)

Твой продукт — `data/manifests/pilot.jsonl`. Одна строка = один тестовый элемент:

```json
{"id": "sq-0421-C2",               // уникальный id: источник–№пассажа–категория+номер
 "audio_path": "data/audio/….wav", // звуковой файл
 "transcript": "…",                // точный текст сказанного
 "question": "What color was the speaker's jacket?",
 "category": "C",                  // A, B или C
 "subtype": "absent-attribute",    // A: "stated" · B: "inference" · C: см. Задачу 2
 "gold_answer": "UNANSWERABLE",    // правильный ответ; для C — всегда слово UNANSWERABLE
 "source": "spoken-squad",         // откуда аудио: spoken-squad или tts
 "generator": "gpt-4o-mini/b-v2",  // какая модель/версия промпта сделала вопрос ("native" = исходный вопрос датасета)
 "verified_by": "M3"}              // кто проверил — никогда не создатель
```

Если поле нужно поменять — сообщи всем в тот же день через `docs/decisions.md` (наш журнал решений).

## Задача 1 — Достать аудио и пассажи · до **8 июля**

**Зачем:** сами мы ничего не записываем — готовый датасет даёт аудио + транскрипты + A-вопросы бесплатно.

1. Скачай тестовый сплит Spoken-SQuAD с HF: [AudioLLMs/spoken_squad_test](https://huggingface.co/datasets/AudioLLMs/spoken_squad_test) (в Python: `datasets.load_dataset(...)`). Запасные: [alinet/spoken_squad](https://huggingface.co/datasets/alinet/spoken_squad), [официальный GitHub](https://github.com/Chia-Hsuan-Lee/Spoken-SQuAD) — осторожно, полное аудио там ~50 ГБ; бери только нужное.
2. Отбери **40 пассажей**: длина 20–60 с, чистый голос, в транскрипте минимум 3 конкретных факта (имена, числа, даты) — факты и есть сырьё для вопросов. Сохрани список в `data/generation/passages.csv` (id, транскрипт, длительность, число фактов).
3. Категория A бесплатно: для каждого пассажа оставь 1 исходный вопрос с ответом из датасета.
4. Напиши `data/generation/tts_fallback.py` на [edge-tts](https://github.com/rany2/edge-tts) (бесплатно, без регистрации): даёшь текст — получаешь wav 16 кГц моно. Это подстраховка, если какой-то аудиофайл битый.

**Готово, когда:** в passages.csv 40 строк, аудио играет, у каждого пассажа есть A-вопрос, TTS-скрипт делает играющийся wav из любого предложения.

## Задача 2 — Сгенерировать B- и C-вопросы · до **9 июля**

Используй любой сильный чат-ИИ (уровня ChatGPT). Вставляй всегда **транскрипт**, никогда аудио. Генерируй **втрое больше нужного** (цель после фильтров: 30–40 на категорию). Точные тексты промптов храни в `data/generation/prompts/` с версиями в имени (`b-v1.txt`, `c1-v1.txt`, …) — улучшил промпт → сохрани как v2, не перезаписывай.

Промпты (готовы к копированию):

- **B — ответ нужно вывести, а не процитировать** (`b-v1.txt`):
  > Here is a transcript of a short audio passage: "{transcript}". Write ONE question whose answer is NOT stated word-for-word but CAN be logically inferred from the transcript (negation, comparison, simple arithmetic, cause/effect). Also give the correct answer and quote the sentence(s) the inference rests on. Do not ask yes/no questions. Format: QUESTION: … ANSWER: … EVIDENCE: …
- **C1 — про то, что вообще не упоминалось** (`c1-v1.txt`):
  > …Write ONE natural question about a person, object, or place that is NEVER mentioned in the transcript but plausibly could appear in such a passage. The transcript must contain NO information to answer it. Not a yes/no question. Format: QUESTION: …
- **C2 — вещь упомянута, свойство не названо** (`c2-v1.txt`):
  > …Pick an entity that IS mentioned. Ask about one of its attributes (color, size, age, price, reason, time…) that the transcript does NOT give. Not a yes/no question. Format: QUESTION: … ENTITY: …
- **C3 — ложная предпосылка** (`c3-v1.txt`): вопрос, предполагающий то, чему транскрипт противоречит (правильная реакция — возразить). *Только в дефолтном объёме Уровня 2.*
- **C4 — не по теме** (`c4-v1.txt`): вопрос из совсем другой области. *Только Уровень 2.*

Затем прогони свой фильтр `data/generation/filter.py`, который автоматически отклоняет: да/нет-вопросы; C-вопросы, чьи ключевые слова встречаются в транскрипте (обычное + fuzzy-совпадение — такие могут быть отвечаемы!); дубликаты внутри пассажа; вопросы короче 5 или длиннее 25 слов.

**Готово, когда:** в `candidates.jsonl` ≥90 кандидатов B и ≥180 кандидатов C, у каждого заполнен `generator`, а лог фильтра показывает, что и почему отклонено.

## Задача 3 — Верификация и заморозка · до **10 июля** ⚠ эксперимент M3 ждёт этого

**Зачем:** вопросы генерировал ИИ — значит, ИИ и ошибался. Ошибки ловят люди. Этот протокол идёт и в data card.

1. Отдай каждого кандидата проверяющему, который **его не создавал** (генерировал ты → проверяют M1 и M3; поровну, ~60–90 элементов на человека ≈ 30–45 минут).
2. Проверяющий отвечает на четыре вопроса по элементу: (а) верна ли метка категории/подтипа? (б) для B — вывод правда работает и ответ один? (в) для C — вопрос действительно неотвечаем **по транскрипту** (не сказан И не выводится)? (г) звучит ли вопрос естественно?
3. Вердикты: `ok` / `fix` (поправить, тот же человек перепроверяет) / `drop`. Вердикты пиши в `data/generation/verification.csv`.
4. **Калибровка:** первые 20 элементов M1 и M3 проверяют независимо, а ты считаешь % совпадения вердиктов. Меньше 80% → втроём обсуждаете правила, выравниваетесь и только потом продолжаете. Это число согласия — в data card и на твой слайд: оно твоё доказательство доверия.
5. Балансировка и заморозка: всего 90–120 элементов, минимум 30 на категорию, C распределён по подтипам, `verified_by` заполнен везде. Коммит `data/manifests/pilot.jsonl` в PR с пометкой `pilot-freeze`. После заморозки правок нет; исправления = новый файл `pilot_v2.jsonl` + запись в журнале решений.

**Готово, когда:** твой валидатор `data/generation/validate.py` проходит (поля на месте, id уникальны, аудио существует) и число согласия посчитано.
