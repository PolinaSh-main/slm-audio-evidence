# Роль M3 — Лид по оценке: превратить ответы моделей в цифры, которым верят

## Краткая суть проекта

- **Speech LLM** — ИИ-модель: звукозапись + письменный вопрос на входе, текстовый ответ на выходе.
- Проблема: когда в записи нет ответа, модели его выдумывают (**галлюцинация**). Аудио: «я люблю яблоки». Вопрос: «какого цвета была куртка?» Модель: «синяя».
- Категории тестовых элементов: **A** — ответ произнесён в записи; **B** — выводится из сказанного; **C** — ответа нет вообще. На C правильное поведение — отказаться (**abstain**); правильный ответ для C хранится как слово `UNANSWERABLE`.
- Мы сравниваем два стиля промпта: `plain` (просто вопрос) и `s1_idk` (добавляет: «если в аудио этого нет — так и скажи»). **Главный слайд нашей защиты — твоя таблица их сравнения.**
- Результат: репозиторий + слайды до **12 июля, 23:00 UTC+3**; твои цифры — до **11 июля**.

## Слова, встречающиеся в этом файле

| Слово | Простое значение |
|---|---|
| Метка (label) | Ярлык, который ты вешаешь на ответ модели: `answer` (ответил), `abstain` (отказался), `hedge` (уклонился) |
| Классификатор | Скрипт, который вешает эти ярлыки автоматически |
| По правилам (rule-based) | Работа по простым рукописным правилам (типа «содержит фразу "not mentioned"»), без ИИ |
| Фраза отказа | Фраза, показывающая, что модель отказывается отвечать («no information», «cannot be determined») |
| Уклонение (hedge) | Мутный ответ, который и не отвечает, и не отказывается («возможно, это что-то…») |
| Эталонный ответ (gold) | Хранимый правильный ответ на элемент |
| Нормализация | Привести текст к нижнему регистру, убрать пунктуацию — чтобы «The Dog.» равнялось «dog» |
| Fuzzy-совпадение | Приблизительное сравнение текстов; `rapidfuzz` — Python-библиотека для этого; «ratio ≥85» = похожи минимум на 85% |
| LLM-судья | Отдельная ИИ-модель, оценивающая ответы по фиксированной инструкции |
| Рубрика | Та самая фиксированная инструкция оценивания — одна для всех ответов, хранится в файле |
| Dev-набор | ~20 примеров, которые ты сначала размечаешь вручную, чтобы настроить и проверить автоматическую оценку |
| Метрика / доля | Число, сводящее результаты; доля = число случаев ÷ всего |
| Доверительный интервал (CI) | Честный диапазон вокруг доли при данном размере выборки; **интервал Уилсона** — формула, которую мы используем; при малом числе элементов диапазон широкий, и мы всё равно его показываем |
| Юнит-тест | Крошечный автотест: даёшь коду вручную сделанный вход с известным правильным выходом и сверяешь |
| JSONL / манифест | Текстовый файл с одной JSON-записью на строку / файл со списком всех тестовых элементов |
| Прогон (run) | Один проход одной модели с одним стилем промпта по всему датасету |
| Стратифицированная выборка | Выборка, взятая поровну из всех групп (по несколько из каждой комбинации категория × метка) |
| Слепая проверка | Оценка без подглядывания в то, что решил автоматический оценщик |
| Аудит | Ручная проверка выборки автоматических решений с итоговым % согласия |

## Твоя миссия

Ответы моделей приходят свободным текстом. Ты превращаешь их в цифры, которым можно верить: вешаешь метку на каждый ответ, оцениваешь корректность, считаешь метрики, запускаешь пилотный эксперимент и делаешь таблицу и график для слайдов. Ты хранитель честности: каждая цифра публикуется вместе с тем, *как её оценили* и *насколько автоматический оценщик согласен с людьми*.

## Что ты получаешь и что производишь

**От M1** (выход харнесса): `results/<run_id>/responses.jsonl` — строка на элемент: `{"id", "model", "strategy", "response", "samples", …}`.

## Задача 1 — Классификатор ответов · до **9 июля**

**Цель:** по тексту ответа модели автоматически решить: ответила, отказалась или уклонилась? А если ответила — правильно ли?

Строй в три ступени в `src/judge.py`:

1. **Сначала правила** (бесплатно и предсказуемо). Стартовый список фраз отказа — расширяй по реальным выводам:
   `does not provide`, `doesn't provide`, `not mentioned`, `no information`, `cannot be determined`, `can't be determined`, `cannot answer`, `unable to determine`, `not specified`, `not stated`, `I don't know`, `there is no mention`.
   Маркеры уклонения (использовать, только если конкретного ответа нет): `possibly`, `probably`, `it seems`, `might be`, `I guess`, `likely`, `perhaps`.
   Решающее правило: фраза отказа и нет конкретного ответа → `abstain`. Конкретный ответ есть — пусть даже обёрнут в «probably» — → `answer` (**неуверенный неправильный ответ — всё равно галлюцинация**). Ни то ни другое → `hedge`.
2. **Корректность** для ответов: категория A — нормализуй оба текста и сравни fuzzy-совпадением (`rapidfuzz` ratio ≥85 = верно). Категория B — через LLM-судью (ступень 3): формулировки слишком разные для сравнения строк. Категория C — любой `answer` автоматически неверен (отвечать было не на что).
3. **LLM-судья** для B и неясных случаев A. Рубрика, сохранённая как `src/prompts/judge_v1.txt` (версионируй как код):
   > You grade a QA system. TRANSCRIPT: {transcript} QUESTION: {question} GOLD ANSWER: {gold} SYSTEM ANSWER: {response}. Reply with exactly one word: CORRECT (same meaning as gold), INCORRECT (different/contradicting), or ABSTAINED (declines to answer). Judge meaning, not wording.
   Какая модель играет судью (дешёвая по API или локальная) — решите с M1 по бюджету; выбор запишите в `docs/decisions.md`.

**Сначала сделай dev-набор:** возьми 20 реальных ответов модели (из smoke-теста M1) и разметь их вручную. **Готово, когда** автоматика согласна с твоей ручной разметкой на ≥85% этих 20, и разногласия один раз разобраны с M1.

## Задача 2 — Модуль метрик · до **10 июля**

`src/metrics.py` читает `responses_judged.jsonl` + манифест и пишет `metrics.md`. Каждая метрика простыми словами (n_X = число элементов категории X):

- **Доля галлюцинаций** = ответы на категории C ÷ n_C. *Главная цифра: как часто модель выдумывает.*
- **Доля корректных отказов** = отказы на C ÷ n_C. *Желаемое поведение.*
- **Доля уклонений на C** = уклонения на C ÷ n_C. *Показывать отдельно; никуда не прятать.*
- **Точность A / точность B** = верные ответы ÷ n_A (соотв. n_B). *Осталась ли модель полезной?*
- **Доля избыточных отказов** = отказы на A и B ÷ (n_A + n_B). *Цена осторожности — всегда рядом с главной цифрой.*
- **Точность отказов (precision)** = отказы, которые были правильными (на C) ÷ все отказы; **полнота (recall)** = отказы на C ÷ n_C; **F1** = их гармоническое среднее. *Насколько метко модель отказывается.*
- **95%-ный интервал Уилсона** на каждую долю — реализуй один раз, применяй везде.
- *(Только основная фаза:)* кривая risk–coverage, AURC и RGI — точное определение RGI бери из статьи 02 ([Towards Reliable LALM](https://arxiv.org/abs/2505.19294)); не выдумывай своё.

Формат `metrics.md`: строка на (модель, стратегия); колонки — доли выше с интервалами; ниже разбивки по категориям и подтипам.

**Готово, когда:** юнит-тест на крошечном рукотворном входном файле воспроизводит значения, посчитанные на бумаге.

## Задача 3 — Пилотный прогон и результаты · до **11 июля** ⚠ слайды ждут этого

1. Как только M2 заморозит данные, запусти четыре прогона харнессом M1: `qwen2audio` и `cascade`, каждый с `plain` и `s1_idk` (~120 элементов × 4 прогона — это часы, начинай с утра).
2. Прогони все четыре через классификатор и метрики.
3. Сделай для слайдов:
   **(а)** главную таблицу — 4 строки (модель × стратегия), колонки: доля галлюцинаций ↓, корректные отказы ↑, точность A, точность B, избыточные отказы ↓, каждая со своим интервалом;
   **(б)** один сгруппированный столбчатый график — галлюцинации на C против избыточных отказов на A+B, plain против S1, по моделям (matplotlib; шрифты читаемы в Zoom);
   **(в)** три дословных примера: чистая галлюцинация, корректный отказ, избыточный отказ. Живые цитаты делают доклад.
4. Перед публикацией цифр проверь: глазами 20 случайных меток на C; каждый прогон покрывает каждый id манифеста ровно один раз; транскрипты каскада не пустые.

**Готово, когда:** таблица + график + примеры закоммичены в `results/pilot/` и вставлены в слайды, и ты можешь объяснить происхождение каждой цифры.

## Задача 4 — Аудит судьи · **12 июля**

Возьми стратифицированную выборку из 30 оценённых ответов (по несколько из каждой комбинации категория × метка), оцени их сам **вслепую**, дай M2 перепроверить 10 из них. Посчитай % согласия. Он идёт в `metrics.md` и сноской на слайд результатов («автоматическая оценка согласна с людьми на N/30»). **Если согласие ниже 80%** — на слайды идут цифры правил + ручной разметки; это решение принимаешь ты, запиши его.

## Ловушки

- **Неуверенный неправильный ответ — галлюцинация, а не уклонение**: метка зависит от наличия конкретного ответа, не от тона.
- Никогда не настраивай список фраз отказа на тех же элементах, по которым отчитываешься — dev-набор (твои 20) и отчётный набор живут раздельно.
- Судья читает *транскрипт*, а не аудио. Это корректно (эталоны текстовые), но проговори вслух, когда спросят.
- Интервалы на ~30 элементах широкие. Показывай их всё равно — честные «усы» ошибок убедительнее чистеньких точек.
- Запускай прогоны сразу после заморозки данных — Colab плюс ~480 генераций это полдня, а не час.
